# VDJ Inspector

Аналитика библиотеки VirtualDJ в браузере. История читается из папки `History` (файлы `.m3u` с датой в имени) и из старого `tracklist.txt`. Библиотека — это `database.xml`.

Файлы и настройки остаются в этом браузере. На сервер они не отправляются.

## Запуск на Windows

Дважды щёлкните **vdj-inspector.bat** или **vdj-inspector.vbs**. Отдельно ставить Node.js не нужно.

Файл сначала проверяет компоненты:

1. Node.js 22 уже есть — шаг пропускается. Нет — скачивается в папку программы.
2. Файлы программы уже стоят — шаг пропускается. Нет — скачиваются. Первый раз нужен интернет.
3. Если всё на месте, программа сразу открывается в браузере.

Окно с текстом можно закрыть после появления сайта. Свёрнутое окно **VDJ Inspector** не закрывайте, пока программа нужна. Следующий запуск уже без интернета, если компоненты на месте.

**vdj-inspector.vbs** открывает тот же bat.

Импорт: `database.xml` и папка `History`. На Windows она обычно в `%LOCALAPPDATA%\VirtualDJ\History`.

## Запуск вручную

```bash
npm install
npm run build
npm run preview
```

## Синхронизация счётчиков VDJ

На главной странице есть блок **Счётчики VirtualDJ**. Он позволяет записать число проигрываний из импортированной History в атрибут `Infos.PlayCount` файла `database.xml`.

1. Откройте приложение в актуальном Chrome или Edge.
2. Нажмите **Выбрать папку** и укажите папку, в которой непосредственно лежит нужный `database.xml`.
3. Перед синхронизацией проверьте, что импортированы актуальные `database.xml` и History.
4. Нажмите **Синхронизировать с History** и подтвердите действие.

Перед каждой записью создаётся резервная копия `database.xml.backup-...`. Копия перечитывается и сравнивается с оригиналом; если проверка не прошла, запись не начинается. После записи приложение перечитывает файл и сверяет его содержимое. Если проверка записи не проходит, приложение пытается вернуть исходное содержимое. При неудаче отката имя исходной резервной копии показывается в сообщении об ошибке.

Синхронизация изменяет только `Infos.PlayCount`. Треки с нулём проигрываний в History, неоднозначными путями и без блока `Infos` пропускаются. Сопоставление для записи выполняется по нормализованному полному пути файла, а не только по названию.

Ручное изменение счётчика доступно в этом же блоке. Оно также требует подтверждения и создаёт отдельную резервную копию. Перед восстановлением резервной копии текущая база сохраняется ещё в одну safety-копию.

**Важно:** сначала тестируйте синхронизацию и восстановление на копии папки VirtualDJ. Не запускайте запись, пока VirtualDJ одновременно изменяет ту же базу. Не удаляйте резервные копии, пока не убедитесь, что база работает корректно.
